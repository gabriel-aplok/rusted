Rusted

A Cargo-compatible Rust build tool that bootstraps with rustc alone. One content-addressed cache for compiled artifacts, shared across every project on the machine. It can build itself, three stages deep.

Reads Cargo.toml and rusted.toml, resolves crates.io dependencies, writes Cargo.lock, and builds workspaces with path and registry dependencies. No Rust dependencies in the tool itself. Cargo never runs during a build.

Artifacts live in the shared store, so ten projects using the same crates compile those crates once. Warm builds skip rustc entirely through content-addressed hits. Source hashing is cached per machine by size and mtime, and dev builds use incremental compilation by default.

Why a second build tool

Bootstraps with rustc alone

One rustc invocation compiles the whole tool from src/main.rs. No install step, no Cargo, no dependencies. The CI jobs do exactly that on three platforms.

One cache for the machine

Compiled artifacts are content-addressed and shared. Two projects that depend on the same crate version compile it once. Warm builds make zero rustc calls.

Cargo-compatible

Wraps cargo-style manifests, workspaces, resolver 2 features, build scripts, proc macros, profiles, editions through 2024, and pipelined library builds where a dependency publishes its rmeta before its rlib finishes.

Remote cache included

Point RUSTED_REMOTE_CACHE at any S3-compatible bucket. Uploads happen after a successful local build, fetches are verified, and failures fall back to a local build with a warning.

Quick start

rustc 1.85 or newer, curl, and tar. On Windows, curl.exe and tar.exe ship with the system. No shell scripts needed for a Windows build, use scripts/bootstrap.ps1. 

./scripts/bootstrap.sh
./target/bootstrap/rusted new hello
./target/bootstrap/rusted run --manifest-path hello/Cargo.toml
install -m 755 target/bootstrap/rusted ~/.local/bin/rusted

Windows:

.\scripts\bootstrap.ps1
.\target\bootstrap\rusted.exe new hello
.\target\bootstrap\rusted.exe run --manifest-path hello/Cargo.toml

Cache

The store lives at ${XDG_CACHE_HOME:-~/.cache}/rusted/v1, and at %LOCALAPPDATA%\rusted\v1 on Windows. --force rebuilds even on a hit. cache info reports sizes. cache gc --max-size <SIZE> removes least recently used artifacts and skips artifacts held by a running build.

Configuration

Global config lives at ${XDG_CONFIG_HOME:-~/.config}/rusted/config.toml. Keys are manifest, cache_dir, target_dir, jobs, offline, registry.index, linker, and profile.*. Environment overrides are RUSTED_MANIFEST, RUSTED_CACHE_DIR, RUSTED_TARGET_DIR, RUSTED_JOBS, RUSTED_OFFLINE, and RUSTED_RUSTC_LOG.

The default linker mode prefers mold, then lld, then the system linker. A profile or package override wins.

Remote cache

info
Set it and forget it
Set RUSTED_REMOTE_CACHE=s3://bucket/prefix to share artifacts between machines. Credentials come from RUSTED_REMOTE_ACCESS_KEY and RUSTED_REMOTE_SECRET_KEY. RUSTED_REMOTE_ENDPOINT selects a MinIO-style endpoint.

Uploads happen after a successful local build. Fetches are verified before install. Remote failures fall back to a local build with a warning. Offline mode never contacts the remote cache. cache gc --remote applies the same size limit to remote objects.

Self-host

./scripts/selfhost.sh
./target/selfhost/stage2 --version

Stage 0 is built by rustc. Stage 1 is built by stage 0, and stage 2 is built by stage 1. Both stages run the unit suite. scripts/test.sh all runs this loop with a fresh cache and offline mode, then checks that the second build makes zero rustc calls.

Tests

./scripts/test.sh integration

Network tests are gated by RUSTED_NETWORK_TESTS=1. scripts/lock-compare.sh compares Rusted lockfiles with cargo output for six fixtures when cargo is installed.
